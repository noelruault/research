# ---------------------------------------------------------------------------------------------------------------
# where the overhead is
# ---------------------------------------------------------------------------------------------------------------
#
# The container costs tens of bytes, not the ~1% report 16 budgeted for it. The range coder is the cheap part.
#
# component                                      11,121 / 4K        3,546 / 960
# range coder vs its own cross-entropy               +4.46 B            +4.08 B
# header and chunk framing (excl. the 8 B coef)     +17 B              +16 B
# brotli stdin vs the anchor's -o file form           0 B               -1 B
# total                                             +21.46 B           +19.08 B
#
# walls   coded 105,756 B against a 105,751.54 B cross-entropy;  16,704 B against 16,699.92 B
# colour  brotli -q11 26,520 B from 33,363 B raw;  8,690 B from 10,638 B raw
# header  25 B at 4K (magic 4 + version 1 + varints 12 + coefficients 8), 24 B at 960 (varints 11)
#
# The coder's ~4 B at both marks is its terminator: one leading carry-catcher byte plus a five-byte flush, less
# what full-precision interval splitting wins back against the cross-entropy. It does not scale with the file.

# ---------------------------------------------------------------------------------------------------------------
# file layout, SHPC v1
# ---------------------------------------------------------------------------------------------------------------
#
# offset  bytes  field
# 0       4      magic "SHPC"
# 4       1      version = 1
# 5       v      uvarint width
#         v      uvarint height
#         v      uvarint region count
#         v      uvarint wall chunk length
#         v      uvarint colour chunk length
#         8      chroma coefficients aR, aB, little-endian float32
#         ...    wall chunk   - range-coded crack planes under the interleaved V/Hz schedule
#         ...    colour chunk - brotli -q11 of the planar RCT residual
#
# The region count is derivable from the decoded partition. It is transmitted anyway as a 2-3 byte consistency
# check that catches a truncated wall chunk before the colour stream is misread against the wrong region ids,
# and it is paid for in the totals above.

# ---------------------------------------------------------------------------------------------------------------
# round trip - the deliverable
# ---------------------------------------------------------------------------------------------------------------
#
# `lab p4dec <file>.shpc <out>.png` reads the file and nothing else: it decodes both crack planes, floods the
# partition back out of them in raster first-appearance order (the order relabelComponents produces, which is the
# order the colour stream is written against), rebuilds the adjacency graph, and replays the colour predictor.
#
# 11121_4K   0 wrong samples of 24,883,200, max |delta| 0
# 3546_960   0 wrong samples of  1,555,200, max |delta| 0
#
# Stronger than required at the 4K mark: the decoder's output PNG is byte-identical to hd_00011121.png as a file,
# not merely pixel-identical.
#
# Causality is now enforced by the format rather than asserted beside it. The decoder builds its context out of
# the planes it is filling in, so a tap that read undecoded data would produce a different context here than at
# encode time and the round trip would fail. Falsification #12 cannot hide in this path.

# regression fixed on the way through
# ---------------------------------------------------------------------------------------------------------------
#
# `lab wallxexact` and `lab wallx` exited 1 before printing a row. Both assert that one crossplane.go variant
# reprices potts.go's caeBytes exactly. That variant was "base" until report 20 made caeBytes read V(x+1,y);
# the tap set caeBytes now codes is "baseFix". The index was stale, so the assertion compared the illegal coder
# against the legal one and fired on the legality cost - 1,500.19 B at 960x540, 5,536 B at 4K.
#
# Fixed by pointing the cross-check at baseFix (new const wallxRef) and pinned by TestWallxRefRepricesCae.
# The "%.2f%% vs base" column label was also wrong for the same reason and now reads "vs caeBytes".
# No number in the record changes: every published figure comes from the interAsym row, which was never affected.
