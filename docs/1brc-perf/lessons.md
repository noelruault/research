# Lessons — 1brcPerf

Read every cycle. One tight bullet per durable lesson: a gate invocation that works here, a repo gotcha, a class of ticket that keeps failing and why.

- Gate that works, in this order, all from the repo root: `cd 1brc/code/go && test -z "$(gofmt -l .)" && go vet ./... && go build -o bin/1brc . && go test ./...`, then `bash 1brc/scripts/check-correctness.sh` (~40 s), then `ARM="<flags>" bash 1brc/scripts/check-correctness.sh` for any arm you are about to time, then `bash 1brc/scripts/experiment.sh --self-test`. Run ALL of them before launching a timed run — a build during hyperfine voids the invocation.
- A timed 1b run at `-r 10` is ~12 min (3 arms × 11 runs × (1.3 s + 20 s cooldown)) and exceeds the 600 s Bash ceiling, so it MUST be the background task's own command. Not `nohup … & sleep 5`: the task's process group dies when that command exits, which killed the first `lanes-requiet` attempt mid-bracket.
- `measure-when-idle.sh` has been operator-overridden to measure NOW (`IDLE_MIN=0 QUIET_LOAD=6.0 QUIET_FORCE=1`, 2026-09-04), but every knob is `${VAR:-default}`. A ticket whose question NEEDS a quiet machine passes its own `IDLE_MIN=600 QUIET_LOAD=4.2 QUIET_FORCE=0 QUIET_WAIT=28800` on that one invocation, rather than editing the operator's defaults for the whole loop.
- Ledger a member the moment its code is green, not at the end of the cycle. `loop-next.sh` greps `built.md` by literal id, so committed-but-unledgered code (this happened to `busiest-stamp`) is invisible to the selector and gets re-dispatched.
- `scripts/loop-next-selftest.sh` fails PRE-EXISTING on `skill-performance-assembly` and `x-transfer` — the OLD `docs/1brc` loop's selector fixture. It is not in spec.md's gate. Do not try to fix it.
- A timed run must be launched DETACHED or the cycle boundary kills it: three `lanes-requiet` invocations died mid-bracket (two VOID files, one at Benchmark 1) because a background task dies with the cycle that launched it, and the run needs ~12 min PLUS an idle wait of up to 8 h. Recipe, from the repo root: `export PRED='<the prediction>'` and `export LOG="1brc/bench/$(date -u +%Y-%m-%dT%H%M%SZ)-<id>-detached.log"` FIRST — the single quotes below defer their expansion into the inner shell, and an unexported PRED becomes an empty `-p`, which experiment.sh rejects with `must carry a number` — then `bash -c 'set -m; nohup env IDLE_MIN=600 QUIET_LOAD=4.2 QUIET_FORCE=0 QUIET_WAIT=28800 bash 1brc/scripts/measure-when-idle.sh -i <id> -p "$PRED" -a "ptr.a=" -a "<arm>=<flags>" -a "ptr.b=" -r 10 -w 1 > "$LOG" 2>&1 < /dev/null & c=$!; echo "pid=$c"; ps -o pid,pgid,ppid -p $c'` — `set -m` gives the child its OWN process group and the launcher exiting reparents it to launchd, so a process-group kill cannot reach it. The Bash tool's shell is zsh, where `set -m` fails with `can't change option: -m`, hence the `bash -c` wrapper. Verify detachment at launch by comparing the child's PGID to the launcher's.
- Before launching a timed run, check `/tmp/1brc-measure.lock/pid` (and `.../what`): a detached run from an EARLIER cycle may still be waiting for idle. If a live pid holds it, POLL the newest `1brc/bench/*-detached.log` instead of launching — `measure_lock_acquire` would refuse the second run with exit 3 anyway, and that refusal costs the cycle's correctness gate for nothing.
- This branch has a SECOND writer and the selector cannot see it. The operator works in a separate checkout (`/Users/noelruault/go/src/github.com/noelruault/research`, branch `main`) and commits straight onto `1brc-perf`; on 2026-09-04 a full `lanes-requiet` bracket was measured and ledgered as E-38 at 23:31, one minute BEFORE this loop launched its own run for the same ticket, and `loop-next.sh` still selected it because the row never reached `built.md`. So after the rebase, `git log --oneline -8` and grep the ledger for the selected ticket's name before spending a gate on it — the rebase being "up to date" only means nothing was pushed, not that nothing was committed.
- A measurement taken from the operator's `research/` checkout carries that checkout's provenance, which may be a DIRTY tree and a commit that is not on this branch. Before quoting such a row, verify the timed code with `git diff <header-commit> <cited-commit> -- 1brc/code/go`: on E-38 it was empty, so the number stood, but the header commit did not pin the binary and only the diff established that it did.
- A detached run builds `bin/1brc` at LAUNCH but writes its provenance header after the wait, so a run that waits hours records whatever commit exists when the machine finally goes idle, not the one its binary came from. Two consequences: never touch `1brc/code/go` or run `go build` while a detached run is waiting (it would swap the binary under the pending hyperfine, the same trap as rebuilding mid-invocation), and when the row lands, confirm `git diff <header commit> <launch commit> -- 1brc/code/go` is empty before quoting it. The 2026-09-04T213210Z run was launched with the Go tree at `857911b` and nothing in that cycle touched it.
