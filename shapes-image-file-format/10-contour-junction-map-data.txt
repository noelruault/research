# Contour coder, bottleneck B2: the JUNCTION MAP (contourBytes, code/lab/contour.go:64).
#
# The contour coder is the wall coder actually chosen below ~6,400 regions at 3840x2160, where walls
# are 92-96% of the file. Every wall result in report 09 improves CAE and is worth zero in that band.
# This file measures the junction map -- the context-coded sparse bitmap at contour.go:97-105 that
# tells the decoder where the wall junctions are, and which uses the same 10-bit / 1024-model context
# width that report 09 proved under-conditioned at 4K for the CAE V-plane.
#
# command : labx csplit / cwidth / csel / ccausal   (code/lab/contourctx.go, frozen taps in code/lab/selectedj.go)
# build   : the report-09 build set, i.e. code/lab minus crossplane.go (crossplane.go and wallctx.go
#           both define `tap` and `crackPlanes`, as they did when report 09 was produced)
# eval    : the published flat renders under $SCRATCH/hd/{renders4k,ladder_1920,ladder_960,ladder_512}
# runs    : every table below was produced twice; the two runs are byte-identical.
#
# REPRODUCTION GATE. csplit re-derives contourBytes' own total and refuses to print unless
#   (a) the region count recovered from the render matches the published one to within 0.1%,
#   (b) juncB+dirB+loopB+turnB equals contourBytes to 1e-6 and steps matches exactly,
#   (c) the contour total equals the published one to within 1 B.
# All eleven published 4K contour totals reproduce exactly:
#   19,079 / 24,106 / 29,674 / 37,518 / 45,797 / 56,576 / 72,041 / 93,577 / 126,291 / 167,356 / 224,496 B.
# cwidth adds a second gate: the generalised pricer on the baseline template must equal contourSplit's
# juncB to 1e-6, so a variant cannot be compared against a mis-built baseline.
# Both gates are runnable and both fire: asking csplit for 45,000 B at the 1,383 rung prints
# "CONTOUR MISMATCH: got 45797.48 B, published 45000 B -- stopping" and exits nonzero.

# All ten baseline taps read left-on-the-same-row or a row above; the replay reports 0 mismatching

# One real but negligible bookkeeping gap was found: the loop channel pays log2(nv)+2 per closed loop
# but sends no count and no end-of-loops flag, so a decoder cannot tell when the loop list stops.
# Repairing it costs one flag bit per loop plus one terminator: 10.8 B of 19,079 B at 227 regions
# (0.06%), 66.5 B of 45,797 B at 1,383 (0.15%), 277 B of 93,577 B at 6,417 (0.30%). Recorded, not fixed.

# Read-off.
#
# (a) The direction of report 09's result transfers and the magnitude does not.
#     At 512x288 and 960x540 the best width is 10 bits at every single mark -- the published context is
#     already right and every wider template is worse, by up to +5.5%. At 1920 and 4K wider templates
#     start to pay. Same sign as report 09's frozen 16-tap CAE template, two orders of magnitude smaller:
#     -10.32% on the CAE V-plane at 4K against -0.82% here at the best case.
#
# (b) Sparsity, not sample count, is the binding constraint. The V crack plane has 8.29M samples of
#     which ~600k are ones at 11,121 regions; the junction lattice has 8.29M samples of which 7,687 are
#     ones at 6,417 regions. Widening from 1,024 to 65,536 models divides an already tiny positive
#     population across 64x the bins, and the learning cost eats the conditioning gain almost exactly.
#
# (c) At the coarsest marks the 10-bit context is already costing more than no context at all.
#     4K, 227 regions: junc10 = 510 B, order0 = 503 B, combLB = 502 B, staticH10 = 497 B. The context
#     coder pays 1.4% MORE than a memoryless coder would, because 1,024 models are being learned to
#     describe 244 junctions. An enumerative coder naming the positions outright would cost 502 B, so
#     the entire prize on this channel at this operating point is 8 B of a 19,819 B file: 0.04%.
#
# (d) The junction map's share SHRINKS with resolution, which is why report 09's lever cannot repeat here.
#     Junction count is fixed by the region count; turn count scales with boundary length, i.e. with the
#     linear dimension. At the coarsest mark of each ladder the junction map is
#       512x288    199 regions   381 B of  2,731 B  = 13.95% of the contour bill
#       960x540    239 regions   480 B of  5,277 B  =  9.10%
#       1920x1080  217 regions   523 B of  9,608 B  =  5.44%
#       3840x2160  227 regions   510 B of 19,079 B  =  2.67%
#     4K is where the junction map matters LEAST. Report 09's finding was that 4K is where the CAE
#     context matters MOST. The two are not the same lever pointed at a different component.
#
# (e) Paid for in full: nothing. The frozen template needs no side information (it is a compile-time
#     constant, as caeBytes' own template is), no second pass, no mode flag. It costs 64x the model
#     tables -- 65,536 binary models against 1,024 -- which is an encoder/decoder memory cost, not bytes.
#     There is no accounting trick hiding a larger win; the win is simply not there.

### 4. VERDICT -- clean negative, and a redirect
#
# The junction map is not bottleneck B2. It is 2.6-9.3% of the delivered file across the band where the
# contour coder is chosen, it is already within 1-2% of its own memoryless and enumerative floors at the
# coarse end, it is causally sound, and widening its context by greedy selection at the most favourable
# operating point available buys 0.02% to 0.09% of the contour bill at 4K and is strictly negative at
# 512x288 and 960x540.
#
# The contour coder's bill is TURNS: 77-94% of it in the band where it is chosen, at 1.16-1.24 bits per
# turn against a ternary alphabet whose order-3 model has only 27 contexts. That is the component with
# the untouched-to-share ratio, and it is the other half of this task, held by a separate agent.
#
# A better second target than the junction map is the loop channel. At 1,383 regions it is 1,658 B --
# 3.6% of the contour bill, and nineteen times the 85 B that the junction map's own free-tables ceiling
# is worth at the same point. It is paid as a flat log2(nv)+2 = 25.0 bits for each of 531 loop starts,
# with no context, no ordering, and no attempt to predict where a loop begins, and it is the one channel
# here with a known correctness gap (section 2). It has never been examined either.
